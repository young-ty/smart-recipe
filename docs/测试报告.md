## 3. 覆盖率（NFR-06）

### 3.1 后端：97%

```
.venv\Scripts\python.exe -m pytest --cov --cov-report=term-missing
```

口径固定在 `.coveragerc`（`source = backend/app`、`branch = True`、`fail_under = 80`），
JSON 报表落在 `.codex-build/coverage-backend.json`。分层结果：

| 模块 | 覆盖率 | 说明 |
| --- | --- | --- |
| `services/generator.py` | 99% | 提示词与注入防护、结构化校验、解析容错、缓存键 |
| `services/recipe_resolver.py` | 99% | 库内 / 生成 / 不可用三分支、当次闸门与落库 |
| `services/dish_text.py` | 100% | 同义写法归一与相似度（库内召回与覆盖率报表共用） |
| `services/recognizer.py` | 96% | 预处理、softmax top-k、降级分支 |
| `api/routes_recipes.py` | 96% | 菜谱解析、详情、类别清单与健康检查 |
| `core/database.py` | 90% | 引擎与 schema 迁移 |
| 合计 | **97%** | 1791 语句（缺 38）、348 分支（缺 25） |

未覆盖的 38 行集中在两类：进程级异常兜底（如 `main.py` 的未处理异常处理器、
`recognizer.py` 的推理异常分支）与只在特定环境才走到的路径（`config.py` 的环境变量默认值、
`database.py` 的迁移边界）。这些分支要触发需要构造进程崩溃或换数据库类型，收益低于成本，
因此保留为已知缺口而不是硬凑用例。`--cov` 会把 80% 作为硬门槛（`.coveragerc` 的 `fail_under`），
覆盖率掉下这条线时命令本身就会失败。

`generator.py` 与 `recipe_resolver.py` 各剩一处：前者是 JSON 扫描器里「转义字符紧接着又遇到
反斜杠或引号」的组合分支（`141 → 143`）；后者是食材名为空时提前 `return None` 的那一行（`126`），
真实数据里不会出现空食材名。两处都要靠构造畸形输入才走得到。

## 4. 性能压测（NFR-01）

```
.venv\Scripts\python.exe backend\tools\perf_probe.py --strict --json-out .codex-build\perf-probe.json
```

**方法与口径**：进程内用 FastAPI `TestClient` 直接调应用（不经网络与 uvicorn，量的是接口自身耗时）；
4 张实拍图轮换（`demo/dishes/`），先热身 2 轮再计时，避免把一次性的 ONNX 加载混进样本；
大模型 Key 显式置空——库外菜走生成会把网络时延混进来，而生成接口另有 8 s 的独立预算；
每次请求都会真实写一条 `recognition_logs`，所以压测用临时数据库，不碰开发库。

**样本**：100 次识别 + 100 次库内检索，串行执行（单机压测，模拟连续使用而不是并发压力）。

| 接口 | 次数 | mean | p50 | p90 | P95 | max | 预算 | 结论 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| `POST /api/recognize` | 100 | 167.3 ms | 166.4 | 172.1 | **175.9** | 194.4 | 500 ms | 通过 |
| `POST /api/recipes/resolve`（红烧肉，库内命中） | 100 | 4.5 ms | 4.5 | 5.1 | **5.2** | 5.6 | 200 ms | 通过 |

**模型**：`dish-convnext-base-208-onnx`，208 类，类别清单已交付，运行时为真实 ONNX 推理
（`degraded = false`），未落入模拟识别分支。

**与早期数字的关系**：README 里记录的单张前向 143 ms 是模型本身一次推理的耗时，
这里的 175.9 ms 是「上传解码 → 预处理 → 前向 → 写识别日志 → 组装响应」的端到端耗时，
两者口径不同，不能互相替换。

## 6. 已知缺口与后续

1. **真实大模型调用不在自动测试里**：`test_generator_live.py` 的 3 条用例需要
   `RECIPE_LIVE_TESTS=1` + 有效 Key + 网络，属人工验收。想跑：
   `$env:RECIPE_LIVE_TESTS=1; .venv\Scripts\python.exe -m pytest backend/tests/test_generator_live.py -q`。
2. **没有浏览器 E2E**：交互由 jsdom 覆盖，真实拖拽手势、样式与首屏时间（NFR-02）需要在浏览器里人工核对。
3. **菜谱库仍有留白类别**：当前登记 55 类（50 类可承接 + 5 类显式缺口），其余 153 类走生成分支，
   不会静默丢弃。用 `backend/tools/coverage_report.py` 看实时分布。
4. **压测不含网络与并发**：测试口径是单机串行接口耗时，不含 uvicorn、反向代理与多用户并发；
   本地演示够用，生产评估需另做并发压测。
5. **训练指标不在本报告**：模型训练与数据集评估不在本报告范围，本报告只覆盖前后端与集成。
